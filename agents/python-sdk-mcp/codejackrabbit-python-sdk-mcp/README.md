# CodeJackRabbit — Python SDK MCP companion

This companion exposes the `code` tool surface (the token-efficient default): two discoverable tools, bounded code execution (`execute`) over the bundled Python SDK and contract-derived documentation search (`search_docs`). The `execute` tool runs each snippet in a separate interpreter placed under an operating-system sandbox: on Windows an AppContainer created with no capabilities (so the snippet can open no network socket at all) inside a Job Object that forbids child processes and bounds memory; on Linux a bubblewrap sandbox with no network namespace, no capability, no /proc and a read-only runtime, whose seccomp filter refuses new programs and processes, any access to another process (ptrace, process memory, pidfd), io_uring, namespaces and mounts. The snippet's file-system reach is limited to the generated SDK package, the Python runtime it needs and one per-call directory, and nothing else. Because the isolated child has no network capability it performs no direct HTTP: the SDK's requests are forwarded over the stdio channel to the server process, which alone reaches the configured API host and alone holds the credentials, so credentials never enter the child. Each SDK operation the snippet calls through the provided client is authorized by the same allowlist, read-only switch and credential preflight as every surface, and an in-process audit hook remains as defense in depth. `execute` is ENABLED BY DEFAULT only when this operating-system isolation is available; where it is not, `execute` is disabled and returns an `execute_disabled` refusal. OMNIWRAP_MCP_EXECUTE=enabled cannot bypass isolation. Set OMNIWRAP_MCP_EXECUTE=disabled to turn it off. `search_docs`, `dynamic` and `operations` are unaffected. Per-operation tools are available only through the explicit `operations` compatibility surface.

This installable companion calls the **bundled generated Python SDK public methods**. It does not call a placeholder facade and does not execute a Java, C#, Rust, TypeScript or JavaScript SDK. Those SDK targets remain independent deliverables.

Install this directory with `python -m pip install .`, or install its built wheel together with its declared dependencies. For an offline installation, provide a local wheelhouse and use `python -m pip install --no-index --find-links <wheelhouse> <companion.whl>`.

Set `OMNIWRAP_MCP_BASE_URL` to the API URL (use the local OmniWrap simulation URL when testing), and set `OMNIWRAP_MCP_ALLOWED_OPERATIONS` to a comma-separated list of exact operation IDs. Set `OMNIWRAP_MCP_READ_ONLY=1` to additionally refuse every tool classified `write` even when it is allowlisted. For secured operations, set `OMNIWRAP_MCP_AUTH_JSON` to a JSON object mapping declared authentication scheme names to secret strings, or set one variable per scheme (`tool-map.json` and `omniwrap-artifact.json` record the exact names under `credential_environment`; a per-scheme variable overrides the JSON entry). A secured tool whose declared security alternatives are not fully configured fails with `credential_missing` before any SDK call. Leave credentials outside tool arguments and source control. An empty allowlist denies every call. There is no default API destination, redirected requests are not followed, and proxy environment variables are ignored.

Every tool carries `access` (`read-only` when the operation's effect signature writes no resource, otherwise `write`, or the operation's `x-omniwrap-mcp-access` extension), its effect signature (`effects`, repeated under `_meta` as `omniwrap/effects`) and `requires_confirmation`, true for an irreversible write; MCP `readOnlyHint`, `destructiveHint` and `idempotentHint` are derived from that signature, an `outputSchema` whose `data` member is typed from the declared success response when it is unwrapped JSON, and MCP annotations. Each tools/call writes one JSON audit line to stderr (`event`, tool, operation, access, outcome code, HTTP status, duration and byte counts); the line never carries arguments, response bodies, upstream messages or secrets.

When the execute tool runs under operating-system isolation, it copies the interpreter once into a per-package sandbox folder under the user's local package store and creates one AppContainer profile; run `python -m omniwrap_codejackrabbit_mcp.server --cleanup-isolation` to remove this package's profile and cached copy. Launch `python -m omniwrap_codejackrabbit_mcp.server` using the Python interpreter where this package is installed. `mcp.json` is the corresponding agent-host configuration; replace its empty URL and allowlist values before connecting. The stdio wire uses newline-delimited JSON-RPC. It supports initialize, tools/list (20 tools per page), tools/call and ping.

Inputs keep their wire names in path/query/headers/cookies groups and a body field. The adapter maps them to the exact public Python method arguments. JSON Schema validation runs in a separate process with a five-second deadline and no remote reference retrieval. Mixed request media require an explicit `content_type`. Mixed streaming responses expose `stream_response`, matching the SDK response mode.

Runtime limits: `OMNIWRAP_MCP_TIMEOUT_SECONDS` (15 by default; per HTTP timeout and checked stream deadline), `OMNIWRAP_MCP_MAX_RESPONSE_BYTES` (4 MiB), `OMNIWRAP_MCP_MAX_RESULT_BYTES` (1 MiB), `OMNIWRAP_MCP_MAX_STREAM_EVENTS` (100), and `OMNIWRAP_MCP_MAX_RETRIES` (0, at most 3). Compressed responses are refused so the byte bound applies before decoding. Streams close on completion or limit failure. SDK errors preserve their type/status/attempt count with sanitized messages; configured secrets are redacted from successful results.

`tool-map.json` records exact SDK method bindings, typed schemas and omitted operations with reasons. Binary and multipart uploads, unresolved/dynamic schema resources and credential-carrying operation parameters require dedicated adapters. This companion performs one operation per tool call; it does not automatically traverse pages or acquire OAuth tokens.
